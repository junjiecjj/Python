# Data directory

Expected layout for real datasets:

```
data_root/
├── train/
│   ├── rdm/
│   │   ├── sample_000001.npy
│   │   └── ...
│   └── mask/
│       ├── sample_000001.npy
│       └── ...
├── val/
│   ├── rdm/
│   └── mask/
└── test/
    ├── rdm/
    └── mask/
```

RDM files (`.npy` or `.npz`; for `.npz` the first array is used):

- complex64 / complex128 arrays of shape `[256, 256, 3]` (channels-last)
  or `[3, 256, 256]` (channels-first). The loader auto-detects the channel
  axis (the smallest dimension) and converts to channel-first.
- If your data stores real and imaginary parts separately (e.g. a real
  array with a trailing axis of length 2, or two separate files), adapt
  `ensure_complex()` in `rdsegnet/datasets/rdm_dataset.py` — that is the
  single hook for custom real/imag conventions.

Mask files:

- `[256, 256]` arrays in the matching `mask/` folder with the **same
  filename** as the RDM. Any nonzero value is treated as foreground;
  masks are converted to binary float tensors.

`data/dummy/` is generated by `scripts/create_dummy_data.py` and contains
random noise — it exists only to verify the code runs, never for drawing
scientific conclusions.
